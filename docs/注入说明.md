# 注入说明 —— CdnImporter.dylib → 世界弹射物语 iOS 1.8.4

本文件说明**这个 dylib 是什么、从哪来、怎么进到游戏包里**，以及怎么换成你自己的服务器地址。

---

## 1. 它是什么

- 一个 **arm64 动态库**（`CdnImporter.dylib`，446,528 字节，sha256 `cf11d70411667e1a9230f25be49393214d03eb91cea580989fe126d6ef846374`）。
- **非越狱方案**：没有任何 `%hook`、不依赖 MobileSubstrate/CydiaSubstrate，也不需要 TrollStore。
  它靠一条 `LC_LOAD_DYLIB` 被 dyld 在游戏进程启动时加载，只在 `__attribute__((constructor))` 里做两件事：
  打几行日志、等 App 起来后挂一个**可拖动的悬浮球**。剩下的全部动作都由你点按钮触发。
- 它跑在**游戏进程内**，所以拥有游戏沙盒的身份：能直接读写
  `<容器>/Library/Application Support/com.leiting.wf/Local Store/asset/asset_download/<子目录>/**`，
  也能通过系统文件选择器（`UIDocumentPickerViewController`）拿到你授权的任意目录（SMB / iCloud / On My iPhone）的**递归读**权限。
- 它**不**改游戏的启动流程、不 hook 客户端逻辑、不联网。导入完成后需要你自己重启游戏，客户端会读 `info.json` 判定资源已就绪。
- **v1.4 的健壮性改动**（与「导入」阶段有关，注入方式没变）：解压逐条目开 `@autoreleasepool`（不再把 10 GB 量级的自动释放分块攒到整轮结束）、输入源读取遇到 `EFAULT/EIO/ESTALE` 会按路径重开文件重试（最多 3 次 × 300 ms）、每条归档的日志末尾带「内存 X」（`phys_footprint`，即 jetsam 依据）。详见 `交付说明.md` 的 v1.4 变更块。

## 2. 它从哪来（可复现）

由 GitHub Actions 工作流 `.github/workflows/ios-importer.yml` 在 **macOS runner** 上用 `xcrun clang` 编译（Windows 上编不出 iOS 产物）。
工作流「编译 dylib 与冒烟注入」作业的步骤（与仓库 `ios/importer/README.md` §2.1 一致）：

```bash
SDK="$(xcrun --sdk iphoneos --show-sdk-path)"
xcrun -sdk iphoneos clang -arch arm64 -dynamiclib \
  -isysroot "$SDK" -miphoneos-version-min=14.0 -fobjc-arc -O2 -Wall \
  -DCDN_IMPORT_PATCH_BASE=@\"http://<你的服务器>:8001/patch/cn/\" \
  -install_name @executable_path/Frameworks/CdnImporter.dylib \
  ios/importer/*.m \
  -framework UIKit -framework Foundation -framework UniformTypeIdentifiers -framework CoreGraphics -lz \
  -o CdnImporter.dylib
codesign --force --sign - CdnImporter.dylib
```

- `-DCDN_IMPORT_PATCH_BASE=…` 决定写进 `info.json` 的 `baseUrl` 字段（它只服务 Recovery 流程，当前服务器 `files_list` 是零字节的 `recovery/empty.csv`，所以这个字段近乎惰性）。
  上面命令里的地址只是**示例**：本包 dylib 由 CI 的 push 触发编译，实际烧进去的是仓库里的占位地址
  `http://192.168.1.10:8001/patch/cn/`（`workflow_dispatch` 的 `patch_base` 输入从未被使用过）。
  想让 `baseUrl` 是你的真实地址，见第 5 节第 2 条。
- 编完做了独立核验（`ipsw macho info`）：`64-bit MachO / Type=DYLIB / CPU=AARCH64`、24 条 load command、
  `LC_ID_DYLIB = @executable_path/Frameworks/CdnImporter.dylib`、`LC_BUILD_VERSION Platform: iOS, MinOS: 14`、
  `cryptid=0`、`LC_LOAD_DYLIB` = UIKit / Foundation / UniformTypeIdentifiers / CoreGraphics / libz.1 / libobjc.A / libSystem.B / CoreFoundation。
  **这个 install name 必须与注入器写进主二进制的那条路径逐字一致**，否则 dyld 找不到它。

## 3. 它怎么进到游戏包里（三步）

```bash
# ① 服务器改址（可选但常用，本交付包已做过）：把官方域名改写到自建服务器。
#    它自带硬断言「ncmds / sizeofcmds 不变」，所以必须在注入之前跑。
node client-patch/build/patch-ipa.mjs --ipa <官方 iOS-1.8.4.ipa> --host <你的服务器> --port 8001 --guard-mode launch --out step1.ipa

# ② 注入导入器：主二进制追加一条 LC_LOAD_DYLIB + 把 dylib 放进 Payload/<App>.app/Frameworks/
node ios/importer/tools/inject-dylib.mjs --ipa step1.ipa --dylib CdnImporter.dylib --out step2.ipa
#    加 --dry-run 只做断言不落盘（推荐先干跑一次，看 16 条断言全 ✓ 再真跑）

# ③ 侧载：Sideloadly（Windows 可用）拖入 step2.ipa，填自己的 Apple ID，重签并安装。
#    它会连带重签嵌套的 dylib。免费账号签名 7 天到期，重签是原地覆盖安装：
#    游戏数据容器保留，已导入的 10.19GB 资源不需要重做。
```

> **顺序不能反**：`patch-ipa.mjs` 里有「ncmds / sizeofcmds 必须不变」的硬断言（它假设自己不碰 load command 区），
> 所以必须先改址、后注入。本交付包的 `wf-ios-1.8.4-已注入.ipa` 已经按这个顺序做好（改址 39 条断言 + 注入 16 条断言全过）。

注入器（`工具/inject-dylib.mjs`，纯 Node，Windows 上可跑）做了什么：

- 定位主二进制（`Payload/<App>.app/<App>`；找不到时读 `Info.plist` 的 `CFBundleExecutable` 兜底）。
- 在**命令区末尾**（偏移 `32 + sizeofcmds`）写入一条 `LC_LOAD_DYLIB`，`cmdsize` 按 8 字节对齐
  （install name 34 字符 → 72 字节），随后 `ncmds+1`、`sizeofcmds+72`。
- dylib 条目写进 **install name 指向的位置**（`@executable_path/` 前缀剥掉后拼到 app 目录 ⇒ 默认
  `Payload/<App>.app/Frameworks/CdnImporter.dylib`），mode `0755`，紧跟主二进制条目。
  **条目名跟着 install name 走、不跟你手里的文件名走**：把文件改名成 `xxx-append.dylib` 再注入，条目名仍是
  `Frameworks/CdnImporter.dylib`（否则 dyld 按加载命令去找会找不到，侧载后启动即 `Library not loaded`）。
- 落盘前跑 **16 条断言**，任一条失败就抛错且**不写文件**。关键几条：主二进制 `cryptid=0`、头部余量足够、
  **待写入的 72 字节原本全为 0**、文件总长度不变、原有 load command 逐字节不变、所有 section 的偏移/尺寸一个都不动、
  回读主二进制与 dylib 与内存一致、其余条目内容不变。报告写到 `<out>.build-report.json`。
- 幂等：对已注入过的 IPA 再跑一次不会重复写命令、不会重复加条目。

本包实际结果（`报告/build-report-注入.json`）：`ncmds 67 → 68`、`sizeofcmds 7584 → 7656`、
主二进制长度 108,757,200 不变、section 全部不变、条目 3568 → 3569、写入位置 `@7616..7687` 原本全 0。

## 5. 换成你自己的服务器地址

三种情况：

1. **只是想让客户端连你自己的服务器** —— 不用换 dylib，换的是 `patch-ipa.mjs` 的 `--host/--port`
   （它改的是游戏二进制里 137 个域名站点 + 1 处 ABC 常量池）。dylib 里的 `baseUrl` 只服务 Recovery 流程，通常无所谓。
2. **连 `info.json.baseUrl` 也想换成你的地址** —— 重新编译 dylib：
   - 走 CI：GitHub → Actions → `ios-importer` → Run workflow，`patch_base` 填 `http://<你的IP>:<端口>/patch/cn/`；
   - 或本地 Mac：照第 2 节的命令改 `-DCDN_IMPORT_PATCH_BASE`。
   然后重跑第 3 节的 ②③ 得到新 IPA（**不要**在已注入的 IPA 上直接覆盖注入，用「改址 → 注入」的原始顺序重做）。
3. **运行期临时覆盖**：设备上导入器读 `NSUserDefaults` 键 `CdnImporterPatchBase`，可在越狱前的调试环境里改；正式使用不必碰。

## 6. 失败与回退

- 注入器报错 = 断言没过，**没有写出任何文件**，直接看错误信息里点名的那条断言即可。
- 侧载后游戏启动黑屏：AIR 运行时对 load command 区敏感（B0 报告过类似案例）。回退办法 = 侧载
  `变体\wf-ios-1.8.4-未注入.ipa`（同样改过址、但没有 dylib）。数据不会丢。
- 游戏起得来但**没有悬浮球**：先看日志是否生成（见 `导入说明.md` 第 6 节）。日志有、球没有 ⇒ 覆盖窗口没挂上；
  日志都没有 ⇒ dylib 没被加载（install name 不匹配 / 签名没带上嵌套 dylib）。

## 7. 与 iOS 登录插件的悬浮球同层共存

登录插件（`SpLogin`）和导入器各自挂一个悬浮球。两边都默认贴右边、窗口等级都在 `UIWindowLevelStatusBar` 之上，
早期版本里导入器的球会压在登录插件的球上面（导入器 1120 > 登录插件 1100），触摸被导入器的窗口先接走
⇒ 登录插件的球点不动、「插件没法用」。v1.2 起改成**同层规则**：

| 规则 | 做法 | 结果 |
| --- | --- | --- |
| 发现别人的悬浮层就挂进去 | 把导入器的球直接加进**登录插件那个窗口**的根视图 | 真正的同一图层，不存在窗口等级之争 |
| 默认位置让开 | 同层时球默认贴**左边**（登录插件的球默认在右上） | 一眼看到两个球，互不遮挡 |
| 等级永远更低 | 没有对方窗口时才用自己的窗口，等级取 `UIWindowLevelStatusBar + 90` | 低于登录插件的 1100，绝不压它 |
| 重叠自动避让 | 布局时两球相交（±8pt）就先镜像到左边，左边也不行再退到对方下方 | 怎么拖都不会吃掉对方的触摸 |

识别对方按命名约定：窗口 / 根控制器 / 根视图类名里含 `Overlay`、`SpLogin`、`Floating`、`Ball`、`Pass` 之一，
且窗口等级在 `UIWindowLevelNormal` 与 `UIWindowLevelAlert` 之间、`hidden == NO`；球本身先按
`accessibilityLabel = @"SpLogin 服务器绑定"` 认，认不到就退化为「36–88pt 的方形子视图」。
复查在**看门狗（2 秒）**与窗口可见性通知（`UIWindowDidBecomeHidden/VisibleNotification`）里持续进行，切前后台也会重新同步。

日志里能看到当前宿主（真机日志在 `导入说明.md` 第 6 节那个文件里）：

```
[overlay] 悬浮球已就位（window=… scene=… 宿主=SpLoginPassView（同层，lvl=1100））
[overlay] 悬浮球换宿主：CdnImporterOverlayWindow → 自己的窗口 lvl=1090
[overlay] 悬浮球与登录插件的球重叠，自动让到左侧
```

> 登录插件进游戏后会把整套覆盖层停用（`hideBallInGame = YES`，窗口 hidden），这时导入器换回自己的窗口（lvl=1090）；
> 回到登录界面它再挂回去。静态检查里有一条纪律：`UIWindowLevelStatusBar + N` 的 N 不得大于 100
> （`工具\lint-objc.mjs`，违规会直接报错）。
