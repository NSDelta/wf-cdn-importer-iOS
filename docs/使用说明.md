# 导入说明 —— 把 CDN 资源铺进游戏容器

前置：已侧载 `wf-ios-1.8.4-已注入.ipa`（见 `注入说明.md`），设备能访问你的服务器 `http://<你的服务器>:8001`。

---

## 1. 要导的东西是什么

| 项 | 值 |
| --- | --- |
| 来源目录 | `<你的 cdn 目录>\` 下的六个目录：`archive-common-full`、`archive-common-diff`、`archive-medium-full`、`archive-medium-diff`、`archive-ios-full`、`archive-ios-diff` |
| 归档数 | **634 个 zip**（common 401 / medium 218 / ios 15） |
| 压缩态大小 | 10,748,428,364 字节（约 10.01 GiB） |
| 展开后 | **137,820 个文件 / 10,191,161,030 字节**（约 9.49 GiB） |
| 目标位置 | 游戏容器内 `Library/Application Support/<app id>/Local Store/asset/asset_download/<子目录>/download/**`（国服 `<app id>` = `com.leiting.wf`；**导入器不要求 bundle id**，见下） |
| 另外写入 | 同级的 `info.json`（`version=1.4.54`、`assetRecoveryInfo=[]`、`totalSize=10191161030`、`assetSizeKind="fulfill"`）|
| 另外删除 | 4 个 partial 标记：`<dummy>/partial_downloaded.json`、`partial_downloaded.platform`、`partial_downloaded_android_thread.json`、`Local Store/partial_downloaded.json` |

- **android 层绝不参与**（`archive-android-*` 共 58 个归档必须**不要**放进来；放进来也不会被认领，只会出现在日志的「未识别」里）。
- **不要求 bundle id / app id**：`Local Store` 上层那级目录名，导入器是**按磁盘证据探测**的 —— 候选 = bundle id 目录 + `Application Support` 下所有目录，哪个里面有 `asset/asset_download` 就用哪个（打分：有 `asset/asset_download` +8、有 `asset` +2、存在 +1、bundle id 相符 +1）；一个都没有（游戏还没跑过）才按 bundle id 预置并创建。面板与日志会打印这一行，例如 `Local Store：com.leiting.wf（与 bundle id 一致）` 或 `Local Store：com.foo.bar（bundle id 是 com.x.y，但游戏把资产写在这个目录）`。要手工指定就设 `NSUserDefaults` 键 `CdnImporterStorageRoot`（绝对路径）。
- 顺序很重要：full（基线 1.4.0）先解，54 步 diff 后解，**同名文件后被先覆盖** —— 导入器自己按计划顺序解压，与你的选择顺序无关，所以随便怎么选都行。
- 条目名形如 `production/upload/00/00401ec42e20c5704dd17f0c612519bf65e586`（hash 即文件名，无扩展名），落到 `<download>/production/upload/00/…`；
  medium 在 `production/medium_upload/**`、ios 在 `production/ios_upload/**`。
- 跳过规则（与官方客户端一致）：以 `/` 结尾的目录项、`.empty`、`.hash` 结尾的条目。

## 2. 把 634 个归档送到设备能读到的地方

导入器按**基名**认领归档，所以归档放在哪个子目录、外面套几层压缩包都不影响。五种途径（选一种即可）：

| 途径 | 做法 | 备注 |
| --- | --- | --- |
| **SMB / NAS（推荐）** | 文件 App → 右上角「…」→ 连接服务器 → 挂载共享，把 `<你的 cdn 目录>` 共享出去 | 归档原地读取，设备容器只占展开后的 9.49 GiB，最省空间 |
| iCloud Drive | 把归档拖进 iCloud Drive | 需要 10 GB 云空间；也可只拷一部分，分批导入 |
| On My iPhone | 用「文件」App 从电脑拷进设备本地 | 设备本地要同时腾出 10.01 GiB + 9.49 GiB |
| tar 分卷 | `node 工具/build-tar.mjs --cdn <你的 cdn 目录> --out <分卷输出目录> --volume-bytes 2000000000` | 把 634 个 zip 打成几个分卷 tar，传输时只需传几个文件；导入器支持 `.tar` 与 `.tar.part.NN` |
| 整包 zip | 把若干归档再套一层 zip | 内层 zip 会被当输入处理（stored 直接取窗口，deflate 先解到临时文件） |

> 已有 Android 的 `cn-cdn.tar.part.00…05`（约 10.88 GB，677 个归档）也能用：它覆盖本计划的 619/634 个归档，
> 缺的 15 个 ios 层归档（96,492,743 字节）可单独补。缺包时导入器会列清单并拒绝收尾（除非你打开「缺包也继续」）。

**空间要求**：可用空间 ≥ `10,191,161,030 + 1GB`。选择器/SMB 路线下归档留在原地，容器里只占 9.49 GiB。

## 3. 设备上的操作（6 步）

1. 确认归档已经在设备能访问的位置（第 2 节）。
2. **进游戏**：进程加载 dylib 后，屏幕边缘出现一个蓝色悬浮球「**CDN**」。
   **注意（v1.3 起）**：如果资源已经完整（`info.json` 版本对得上、`assetRecoveryInfo` 为空、4 个 partial 都不在），球会**主动收起**、不出现 —— 这是正常的，别误判成注入失败。想再导入就删掉 `info.json`，或把 `CdnImporterForceBall` 设为 `YES`。
   拖动可换位置（位置会记住）；点它打开面板。
   默认贴右边；**如果检测到登录插件的悬浮球**，导入器的球会挂进同一个图层并默认贴左边，两个球互不遮挡（见 `注入说明.md` 第 7 节）。
3. 点 **选文件夹**（推荐：一次授权整棵子树，甚至能选 SMB 共享上的目录）或 **选文件**（可多选，`public.data` 类型，`tar`/`tar.part.NN` 也能选）。
   - 选择器用的是「打开」模式（`asCopy:NO`），**不会**把 10 GB 复制进 App 沙盒。
   - **可以一批一批地加**（v1.2 起）：系统选择器的多选一次只能选一批，就分几次点 **选文件夹** / **选文件**，
     六个归档目录分六次加进来也没问题；已经加过的路径会自动跳过（提示「这一批全是已加过的」），
     新加进来的每一项后面会跟一个体检标记：`✓` 名字对上了计划、`⚠️` 名字没对上、`？` 需要预检才能判断（tar 分卷、改名包、整包 zip）。
   - 状态区会一直显示 **`按名字对上计划 N / 634`** 与 **`还缺 M 个 zip`**；这只是快速体检，**权威结论看预检**。
   - 点错了用 **撤销上次**（撤掉最近一批）或 **清空选择** 重来。
   - 输入列表只活在本次运行里（不落盘）：**不要在选到一半时杀掉游戏**，否则列表要重选（已导入的文件不受影响）。
4. 点 **预检**：只做索引与匹配，**不动任何文件**。会显示：识别到的归档数、缺失清单、目标目录现状、可用空间。
   确认「识别到 634 / 缺失 0」再往下走。
5. 点 **开始导入**，然后**保持游戏在前台**（面板会自动禁用息屏）。进度条给出归档进度、已写文件数、压缩态已读字节与预估剩余时间。
   中途可以点 **取消**：取消会保留 partial 标记，游戏下次自己走完整下载流程。
   - 想更严格可以先把 **深度校验** 切到「开」：每个归档额外整包比一遍 sha256（多读 10.7 GB，时间约翻倍），能发现「字节数对但内容被改」的归档。
6. 完成后看终态统计：**`137820 个文件 / 10191161030 字节`** 即与权威终态完全一致（`report/wanted-archives-ios.txt` 是同样口径的清单）。
   然后**重启游戏** —— 本工具不 hook 客户端启动逻辑，重启后客户端会读 `info.json` 判定资源已就绪，直接进游戏不再下载资源。
   导入成功后悬浮球会**自动收起**（v1.3 起：资源完整时不再显示球，不挡屏幕；找回办法见第 6 节）。

### 3.1 目标目录（`…/asset_download/<子目录>`）是怎么定的

导入器要写进 `<容器>/Library/Application Support/<app id>/Local Store/asset/asset_download/<子目录>/`
（`download/**` 与 `info.json` 都在这一层）。这个 `<子目录>` **不需要你提前创建**：目录链在写入时按需自建
（`CdnImporterEnsureDirectory` = `createDirectoryAtPath:withIntermediateDirectories:YES`，从 `Local Store` 一路建下去）。

它是**探测出来的**，优先级从高到低：

| 档 | 依据 | 结论标注 |
| --- | --- | --- |
| ① | 某个子目录里已经有 `info.json` 或 `download/` | `[已确证]`（游戏真正在用的目录） |
| ② | 某个子目录里有 `partial_downloaded*` 文件 | `[已确证]`（下载过半的痕迹） |
| ③ | `asset_download` 下只有一个子目录（哪怕是空的，游戏建过） | `[已确证]` |
| ④ | 以上都没有 → 回退参考实现的 `dummy` | `[推断]` |

面板打开时会显示 `目标目录：<依据说明> [已确证] / [推断]`，日志里也会打同一句。

**建议**：进游戏后先让它自己跑一次资源检查（能开始联网下载就行，几秒到十几秒），这时游戏会亲手把目录建出来，
第 ①/③ 档就会命中 —— 之后再导入，写进去的必然是客户端正在用的那个目录。
即使不这么做（直接导入到 `dummy`），客户端启动流程里那两个判定条件（`info.json` 的 `version` 与 `assetRecoveryInfo`）
是**读同一个相对路径**的，所以 `dummy` 也是自洽的；只是万一这台设备的实际目录不叫 `dummy`，导入的文件就白铺了。
另外可用 `NSUserDefaults` 键 `CdnImporterStorageRoot` 直接指定整个 `Local Store` 路径来兜底。

再往上一级（`Application Support/<app id>`）**同样不需要你关心，导入器不要求 bundle id**：
iOS 上这一级既可能是 Info.plist 的 `CFBundleIdentifier`，也可能是 AIR 描述符里的 app id（重签名换过 bundle id
之后两者就可能不一致）。所以它按磁盘证据选：候选 = bundle id 目录 + `Application Support` 下所有目录，
打分（有 `asset/asset_download` +8、有 `asset` +2、存在 +1、bundle id 相符 +1）取最高分；
一个都没有（游戏还没跑过）才按 bundle id 预置目录。面板与日志都会打印这一行，例如
`Local Store：com.leiting.wf（与 bundle id 一致）`、`Local Store：com.foo.bar（bundle id 是 com.x.y，但游戏把资产写在这个目录）`、
`Local Store：com.leiting.wf（游戏还没跑过、没有资产痕迹，按 bundle id 预置）`。

## 5. 为什么这样就够（客户端怎么利用这套文件）

客户端启动时（`GlobalLoading.applyLoad`）：

1. `isDownloaded()`：`partial_downloaded.json` 不存在 **且** `info.json.version` 等于服务器版本 ⇒ 认为已下载；
2. `isAssetComplete()`：`info.json.assetRecoveryInfo == []` ⇒ 认为完整；
3. 两者都成立 ⇒ 直接开始加载，不再下载。

后续的「充足性检查」只做一件事：下载服务器给的 `files_list`（当前是**零字节**的 `recovery/empty.csv`），
逐行 `fileExists(<目标目录>/<path>)`，缺失的写回 `assetRecoveryInfo` 并要求 Recovery。
`info.json` 的 `totalSize` 只用于空间检查，`baseUrl` 只服务 Recovery 下载 —— 所以**导入器只要「铺文件 + 写 info.json + 删 4 个 partial」就足够**，
前提是游戏能正常访问你的服务器接口（那是 `patch-ipa` 改址负责的事）。

## 6. 日志与排查

- 日志文件：设备上 `<游戏容器>/Library/Application Support/CdnImporter/CdnImporter.log`（超过 4 MB 轮转为 `.log.1`）。
- 面板上的 **导出日志** 一次做三件事（v1.3 起，以前只弹分享面板，真机上曾出现「点了没反应」）：
  1. 把整份日志复制到 `<游戏容器>/Documents/CdnImporter.log`（文件 App 里能看到）；
  2. 把**最后 512 KB** 复制进系统剪贴板 —— 面板日志区会打「日志已复制到剪贴板（N 字符）」，随便找个输入框长按粘贴即可发出；
  3. 弹系统分享面板（AirDrop / 存文件 App）。
  即使分享面板没弹出来（v1.3 已改为从最上层窗口 `cdn_present:` 弹出，没有可用窗口时会打「⚠️ 没有可用的窗口来弹出…」），前两条也已经生效。
- 关键行：`[CdnImporter] 目标目录 …`（启动时打印，确认解析到的目录）、每个归档的 `解压 <基名> → <条目数>`、
  收尾的 `终态 <文件数> 个文件 / <字节> 字节`、以及失败时的 `错误：…`。
  每个归档那行末尾还有 **`内存 X`**（v1.4 新增，`phys_footprint`，也就是系统 jetsam 杀进程时看的那个数）：一路平稳才正常，
  如果它随已解压字节数持续爬升，说明内存没被及时释放，请把这行抄下来。
- 常见问题：
  - **没有悬浮球，也没有日志** ⇒ dylib 没被加载（install name 不匹配 / 侧载没重签嵌套 dylib）。
  - **有日志没球** ⇒ ① 先排除「资源已经完整」（v1.3 起这是**正常**行为：球会收起，日志里有「资源已完整（…），收起悬浮球」；想再导入就删掉 `info.json`，或把 `CdnImporterForceBall` 设为 `YES`）；② 不是这个原因才看 `install` 相关报错。
  - **`失败：无法读取磁盘可用空间（…download）：未能打开文件「download」，因为它不存在。`** ⇒ v1.2 的已知 bug（先把目标目录删空、再去探测空间），**v1.3 已修**：现在先 `mkdir` 再探测，探测不到时自动退到最近的已存在目录并打「注意：… 不存在，按最近的已存在目录统计可用空间：…」。看到这句说明还在用旧包。
  - **`读 …/ios-cdn.tar.part.00 失败 (off=…): Bad address`**（跑到一半才炸，例如已读 369 MB 处）⇒ **v1.3 的已知问题，v1.4 已修**，两个成因都堵了：
    ① 解压循环过去没有 autorelease 池，10 GB 量级的读取分块全攒在内存里，分配失败后交给 `pread` 的空缓冲区就是 `EFAULT`（"Bad address"）——
       v1.4 改成**逐条目** `@autoreleasepool`，并在两条分配路径上都加了「内存不足：…」的明确报错；
    ② 分卷放在「文件」App 的 iCloud / File Provider 里时，系统可能在导入途中把本地副本回收（dataless），长时间开着的 fd 再读就失败 ——
       v1.4 遇到 `EFAULT/EIO/ESTALE` 会**按路径重开文件重试**（最多 3 次 × 300 ms，日志有「按路径重开文件后重试（第 N 次）」）。
       仍失败时的提示会告诉你：先重启游戏重试，或**把 6 卷复制到本机目录**（On My iPhone / 应用文档目录）再导入。
  - **预检显示缺失很多** ⇒ 归档没选全（少了 common 或 medium 层），或 android 层的包被误当成 ios 层的了。
  - **导入中途失败** ⇒ 面板会显示哪一条断言/哪个归档/哪个条目失败；失败时**不会**写 `info.json`、**不会**删 partial，游戏会重新走下载流程，不会卡死。

## 7. 注意事项

- **保持前台**：导入期间不要切后台（面板已禁用息屏，但锁屏/切走仍可能被杀）。
- **输入列表不落盘**：分多批选进来的清单只存在内存里。选到一半重启游戏就要重新选一遍（预检会告诉你还缺哪些）。
  已经写进容器的文件不会因为重启而丢。
- **两个球都能点**：和登录插件共存时，导入器的球挂在对方窗口里、默认在左边（独占屏幕时默认在右边）。
  拖动后的坐标记在 `NSUserDefaults` 里（切宿主时按新容器尺寸做一次钳制），重叠时自动避让只在当次布局生效、不改你存的坐标。
  如果一个球点不动，先看日志里的 `宿主=` 与 `重叠` 行。
- **免费账号 7 天重签**：重签是原地覆盖安装，游戏数据容器保留，**已导入的资源不需要重做**。
- **不要手动删 `info.json`**：删了客户端就认为资源缺失，会重新下载。（反过来，想再打开导入器时也是删它或设 `CdnImporterForceBall=YES` —— 见第 6 节。）
- **目标目录不用提前建**（见 3.1）；第一次用之前，最好先让游戏自己跑一次资源检查，让目录被真实创建出来。
- **分卷/归档别放 iCloud Drive**：iCloud（File Provider）里的文件在设备空间吃紧时可能被系统回收成 dataless，导入跑到一半读它就会失败。
  v1.4 已加「按路径重开文件重试」兜底，但仍建议：空间够就放在本机目录（文件 App 的「我的 iPhone」下某个文件夹），
  空间不够就放在 **SMB / 局域网共享**上（导入器按需流式读取，归档不占手机空间，只是慢一点）。
- **6 卷 tar 要在同一次运行里一次选齐**：分卷靠文件名番号（`.part.00/.01/…`）拼成一条逻辑流，缺一卷整包都读不出来。
  输入列表不落盘，所以选完到「开始导入」之间不要杀掉游戏。
- **导入期间不要移动/改名正在读的归档**（尤其是网络共享上的文件）：读的是索引时打开的文件句柄，路径一变就得中止重来。
